# ADR-0002 — provenance precision and bounded search, revision 2026-09-24.1

This additive Services V1 minor revision follows `2026-09-23.1`; the previous sealed bundle remains reproducible. `SafeSource.pageKind` is optional for older clients and is either `work-page` or `capture-page`. Desktop emits the persisted Catalog kind in material detail. New ingest defaults a missing kind to `capture-page`; it never infers a work page from a URL or origin. An explicit work-page needs a safe `pageUrl`. Origin-only input stays capture-page. This preserves the #169 meaning without changing Content V1 DTOs or old source records.

The safe URL rule follows the existing #169 Catalog validator. Ordinary query and hash-based SPA work identifiers survive; credential-bearing keys in a query or twice-decoded fragment, userinfo, dangerous schemes, and direct media paths do not. The server never fetches these URLs.

Search now leases a snapshot only when `nextCursor` exists. Empty and complete one-page answers have no cursor and consume no 10-minute slot. Paginated snapshots retain their opaque identity and bounded per-device/global count and byte budgets; stale or evicted cursors fail with 410. More than 5000 visible hits fails with 400 `INPUT_INVALID`, not a partial snapshot. Existing old Content V1, pairing, LSH and Gateway contracts are unchanged.
