# ADR-0004 — bounded presentation handoff and recyclable search leases, revision 2026-09-24.3

This revision follows the sealed `2026-09-24.2` bundle without changing routes, grant names, pairing, TLS, Content V1, LSH or source provenance. Mobile must consume the complete new bundle and verify its digest; the older seal is not edited.

Presentation offers are claimed only by the Desktop main window and expire after two seconds. An ACK confirming synchronous navigation yields `accepted`. If the claim occurred but its ACK is missing at the deadline, the durable one-time receipt is `handoffStarted`, **not** proof that the target was displayed; retrying the same `opId` replays that receipt without another navigation. An unclaimed or rejected offer returns `PRESENTATION_BUSY`; a rejected opId is retired and its retry returns 410, because a partial local route change cannot be disproved. The opId is durably reserved **before** emitting the offer, so a failed post-navigation receipt write leaves a fail-closed pending row rather than permitting a duplicate presentation. Stop and revoke block new remote admissions while waiting at most for the bounded handoff and database busy window, then retire its offer and remove remote authority. Expired request IDs cannot claim or ACK a new offer. The main renderer measures the native claim's remaining lease with a monotonic clock before navigating so a suspended or reloaded renderer cannot apply a stale claim after revocation.

Search's existing 10-minute lease is a maximum, not a mandatory occupancy period. The final page retires its snapshot. A same-query no-cursor retry reuses a live snapshot. If a different query needs capacity, the server reclaims only the requesting device's oldest lease, with old cursors returning 410; it never evicts another device's lease. Per-device and global count/byte caps remain hard bounds, and an unfit result remains 429. A lost final response can produce 410 on retry; the client starts a fresh search rather than treating that cursor as a new page.
